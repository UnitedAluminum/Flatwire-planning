## 1. What to build

**Hours:** 16 h BE · **Priority:** High · **Sprint:** S3 · **Phase:** 1B · **Stream:** BE

> ⭐ **This is the card that closes the hole `FW-236` opened.** That story added an `FR-074` branch
> failing a push when any tag returns not-`Written`, and left it **compiled but untested** — the
> finding that became `G101`.
>
> ⚠ **Mostly conversion, not authorship.** [`FW-151`](FW-151.md) §5.1 already enumerates **ten
> scenarios and 53 passing assertions** from a harness that was deliberately never committed. This
> story commits them.
>
> ⛔ **Do NOT extract an `IRestClient` to do it.** `CallService`/`WithRoute`/`PostJsonAsync` are
> extension methods on a concrete type in a package we do not own (~60 call sites) — and decisively,
> `TagWriteOutcome` and `OpcWriteStatus` are **private nested types** (`PLCTagService.cs:1036`,
> `:1049`), so a mocked `IRestClient` **cannot construct them and cannot reach the `FR-074` branch at
> all**. `FW-263`'s `Mock<HttpMessageHandler>` stub is cheaper *and* strictly more faithful: it
> exercises the real Polly retry, the real `System.Text.Json` round-trip and the real
> `IHttpContextAccessor` read that `G59` depends on.

**Acceptance Criteria:**
- [ ] `FW-151` §5.1's ten scenarios committed as tests — simulate mode, unconfigured logical name, the `G60` default ids, the real write path, the sentinel, a swallowing read, a genuine mismatch with its compensating re-clear, `IsReadonly`, `SetITInhibit`, and the remaining four operations
- [ ] **Simulate mode makes ZERO outbound requests, `GetOPCInfo` included** — asserted on the stub's recorded request list, not inferred
- [ ] ⛔ **The sentinel (scenario 5): a write the server silently drops but answers `200` reports `Unconfirmed`, NEVER `Confirmed`**, and the trail records `0.0325 (unconfirmed)`. `FW-151` calls this *"the single most falsifiable check in this story"* — it fails if `ConfirmAsync` is ever pre-populated with the written value
- [ ] A failed confirm read is **not** a failed write — it yields `Unconfirmed` with `Success == true`
- [ ] ⭐ **`FR-074`: a refused or faulted tag fails the operation**, and the reason names the count, the tag and the status — `"1 of 1 tags were not written: FL1.FM1.RollGap Refused - …"`
- [ ] ⭐ **A partial batch names only the failures** — 4 outcomes, 2 refused → `"2 of 4 tags were not written"` and only the two failing names appear
- [ ] ⛔ **A bare tag echo from an older `OPCConnection` must NOT fail the push.** The back-compat guard is `attempt.Payload is not null` (`PLCTagService.cs:402`); an echo deserializes to outcomes with a defaulted status, and success is then decided by the confirm read. **This is the branch a naive `FR-074` implementation would have broken**
- [ ] ⚠ **The status crosses the wire as a NUMBER** — `AddControllers()` carries no string-enum converter, so the numeric form is the contract. Pin it
- [ ] The three-record compensation trail asserted in order — attempt, failure, compensating clear — and **flags only, no analogue zeroed**
- [ ] The `P-104` cache holds: a second push issues **no second `GetOPCInfo`**. ⚠ Use a **real** `MemoryCache`; mocking `IMemoryCache` would test the mock
- [ ] ⚠ **`G59`: with a null `HttpContext` the call fails at `GetOPCInfo`, is audited, and no exception escapes** — the background-caller case, not a mistake
- [ ] ⚠ **`G33` is NOT closed by this** — a wrong path reads back consistently wrong, and `[PLC §10.3]` puts that beyond any unit test
