## 1. What to build

**Hours:** 23 h BE · **Priority:** High · **Sprint:** — *(unscheduled and additive to `[CE §3b]`; built 1 Sep 2026 ahead of being scheduled, like the rest of the simulator set)* · **Phase:** 1B · **Stream:** BE

**As an** engineer,
**I want** to drive the simulator over HTTP,
**So that** the console and the automated suites use one control surface.

**Acceptance Criteria:**
- [x] **`POST /sim/{lineId}/run`** — **the one genuinely new route**: scenario, seed, start weight, target and the **target run state**, per `[SIM §8.1]`. It is also what lets a line stopped through `DELETE /sim/{lineId}/run` restart **without a service restart**, which `FW-218` deliberately left out
- [x] ⛔ **Two of those parameters have no lever, so this route REPLACES the line's model rather than mutating a live one.** The seed is `new Random(sim.Seed + (int)line)` in `LineModelBase`'s **constructor** and `StartWeightLb` is `private set`, also constructor-only; `ApplyConfiguration(PassScheduleSnapshot)` carries neither. **Replacing is also what `[SIM §5.7]` requires** — *"the same seed reproduces the same trace, tick for tick"* is only true of a model seeded at construction, and a mid-run reseed would not deliver it. Build the fresh model through the seam's factory, then scenario → target → run state. ⚠ **Do not add a reseed or a set-weight member to `ILineModel`** to avoid the replace. ⚠ **Copy the options, never mutate them** — they arrive as the bound `IOptionsMonitor` instance, so an in-place seed or start-weight override would leak to every line and outlive the request
- [x] ⛔ **The target run state is what makes `Pause` reachable — `G73`.** `SetRunning(line, false)` maps straight to `Stopped`, so **`Paused` and `Idle` cannot be commanded at all today** and `[SIM §4.4]`'s run-versus-line distinction — a line paused with the run still `Running` — has never been demonstrable. `[SIM §9.2]` puts **Start / Stop / Pause** on every panel and the built console has no Pause control. ⛔ **No seventh route**: `DELETE /sim/{lineId}/run` stays the `Stopped` edge `FW-202` is armed by
- [x] **The four built endpoints are re-pointed at the line model, not rewritten** — paths, shapes and semantics unchanged (`P-39`: `/sim` is a *subset* of this story, not a variant). ⛔ **Do not change `OpcFeedSimulator`'s four lever signatures** — a built, verified control surface (`P-266`), and `FW-218` is closed
- [x] ⚠ **The prefix is `/sim`, not `/api/v1/flatwire/sim`** — a separate engineering prefix (`[SIM §8.2]`). It is what the built surface exposes and what `FW-214`'s delivered console calls; moving it strands a shipped tool
- [x] ⚠ **Extended as the existing minimal-API group — not converted to MediatR controllers over `UAController`.** `P-38`: an attribute-routed controller is discovered by the MVC application model and would have to be *un-mapped* by a convention, which is a weaker claim than never mapping it. **The `{data,success,errors}` wire shape is unchanged**, which is all a client depends on
- [x] ⚠ **Routes are not registered at all when no line model is hosted — `404`, not `403`** (`[SIM §2.4]`, `P-38`). A present-but-forbidden control plane is one misconfigured role away from driving a live line. ⛔ **The gate is `FlatWireOpc:SimulateOpcFeed`, not `SimulatePLCTagPush`** — read and write halves of one flag pair; the write half stays `true` until PLC commissioning, so gating on it maps the control plane against a **real** feed. ⚠ Do not "fix" `G66` by adding a role check instead — `[SEC §8.8b]` is explicit that the `404` is the control and the policy is the backstop
- [x] ⛔ **`G70`: widen that condition to *"the readings come from a line model"*** — `SimulateOpcFeed` **or** `UseOpcConnectionDouble` — so `FW-217`'s E2E fixture can be steered. Today it serves each model's default in-spec run and nothing else
- [x] **One seam, satisfied by both hosts.** The handlers resolve an interface carrying the existing lever signatures — `Steer` / `SetRunning` / `DropReadings` / `Peek` plus `FW-213`'s scenario selection — implemented by `OpcFeedSimulator` **and** `OpcConnectionDouble`, instead of taking `OpcFeedSimulator` concretely. ⚠ **No second control surface for the double** (`P-39`); each host already owns a `LineId → ILineModel` map, so this extracts a seam rather than adding a layer
- [x] **The seam carries the model factory too**, because `POST /run` needs it. Both hosts hold a **byte-identical** `private static ILineModel CreateModel(LineId, FlatWireSimulationOptions)` — one factory behind the seam replaces two copies, and it is the only place a line's model is created or replaced. ⚠ **This is the whole of the addition**: `OpcFeedSimulator`'s four lever signatures are unchanged (`P-266`, `FW-218` is closed)
- [x] **Bind `FW-145`'s `SimulatorControl` policy** — `RequireAuthorization(FlatWirePolicies.SimulatorControl)` — **on top of** the conditional registration, never `Operator` (`[SIM §8.4]`). ⛔ **`G72`: the built surface hardcodes `Roles = "Engineer,Admin"`, and `Engineer` is not one of `[SEC §8]`'s six roles** — the column is `Engineering/Maintenance`. Left as it is, the routes keep returning `403` **after** `FW-145` lands, with the same symptom they show now. ⚠ **Do not add an `Engineer` role and do not fall back to a bare `[Authorize]`** — that ships *"any authenticated operator may drive the control plane"*. ⚠ **Standing condition, not a criterion:** `FW-145` issues no role claim yet, so these routes deny every caller today — fail-closed, deliberate, and a hard dependency for the acceptance run
- [x] **`POST /sim/{lineId}/fault` accepts all seven of `[SIM §7.2]`'s faults**, not `FW-218`'s single `DroppedReadings`. `FaultId` was built with all seven and `FW-213`'s twelve scenario-and-fault behaviours are reachable **on the objects only**; the console greys **six of the seven** buttons for want of this route (`G43`). ⚠ An unsupported kind stays **rejected, not accepted-and-ignored** — a fault silently not applied reads as a system that tolerated it
- [x] **`GET /sim/config` — the sixth endpoint (`G68`)**: the active `lbPerFt`, the noise **seed** and the simulation flag. `[SIM §9.2]` asks for `lbPerFt` ***displayed*** and the seed ***"displayed and settable"*** — ⚠ **"settable" is the seed's alone**, and its settable half is `POST /run`'s seed parameter, so **a read closes `G68` completely**. ⛔ **Do not add a configuration write**: a runtime `lbPerFt` setter would decide `Q10` / `OI-45` by the back door, and `P-271` forbids even a compiled default. ⚠ **`lbPerFt` stays nullable** — a `0` reads as a measured factor. ⛔ **Do not widen `SimLineState`**: six fields, fixed as command echo by `P-267`, and `[SIM §9.2]` forbids it
- [x] **`GET /sim/state` returns one snapshot per *hosted* line** so the console needs no poll on load. ⛔ **At most two, and never three** — `FlatWireOpc:IngestLines` decides what is hosted, an empty list is refused at startup, and the standing rule is **`{FL1,FL2}` or `{FL3}`, never all three**: under one answer to `PLC-Q08` polling FL2 and FL3 together would read the same load cell and the same three stands twice a second. `[SIM §8.1]`'s *"all three models' snapshots"* is unreachable **by design, not pending a gap**. ⚠ **An unhosted line is OMITTED and the answer is still `200`** — a short list, which is why the console must never assume three rows. The `400` belongs to the **per-line** routes, which name the reason (`PLC-Q08` / `G30`)
- [x] ⚠ **These belong to no endpoint total.** An engineering surface on a separate prefix — **do not add them to `[API §3.2]`'s index** (`[SIM §8.2]`)

**Rate-card basis:** ⚠ **Re-aimed, not re-priced — the 23 h is not restated here.** It priced *five new* endpoints (4 commands @ 5 h + 1 query @ 3 h, §2, at the **15 Aug 2026 restated** rates; the withdrawn bundled unit test is not priced). ### 6.1 Decisions — `P-306`–`P-314`

| Id | Decision |
|---|---|
| **`P-306`** | ⛔ **`POST /run` REPLACES the line's model; it does not mutate one.** Of `[SIM §8.1]`'s four parameters, **the seed and the start weight have no lever on `ILineModel`** — the seed is `new Random(sim.Seed + (int)line)` in `LineModelBase`'s constructor, `StartWeightLb` is `private set`, and `ApplyConfiguration(PassScheduleSnapshot)` carries neither. ⚠ **Rejected: adding `Reseed`/`SetStartWeight` to `ILineModel`.** Replacing is not the workaround, it is the correct semantics — `[SIM §5.7]`'s *"the same seed reproduces the same trace, tick for tick"* is a property of a model **seeded at construction**, and a mid-run reseed would restart the noise sequence against already-advanced footage, reproducing nothing |
| **`P-307`** | **The seam is `ISimLineHost`, in `FlatWire.Infrastructure`, not Domain.** `SimLineState` is declared there and both implementations live there; minting it in Domain would drag that record across a project boundary or add a mapping layer — **the mistake `P-265` caught one interface over**, where `IReadingSource` was specified and rightly never built. ⚠ `[SIM §2.1]` is untouched: this adds no interface to the **contracts** — not `IFlatWireClient`, not the `[SIG §5.2]` event set, not the shape of a `Reading` |
| **`P-308`** | **`LineModelFactory` extracted, on this codebase's own trigger.** `OpcConnectionDouble` carried the rule in terms — *"If a third consumer appears, extract then — the two copies are cross-referenced so neither drifts unnoticed"* — and `StartRun` is that third consumer. Both byte-identical private copies are gone. ⚠ **`Project`/`Apply` is still NOT extracted**: it has two consumers, and the same rule says wait |
| **`P-309`** | ⛔ **The registration gate is *"a line model is hosted"*** — `SimulateOpcFeed` **or** `UseOpcConnectionDouble` — **not `SimulateOpcFeed` alone.** That is `G70`: with the double mapped the feed **is** synthetic, so `[SIM §2.4]`'s condition was not violated, it was **out of date**. The `404` is unchanged where it matters and was re-measured |
