## 1. What to build

**Hours:** 9 h BE · **Priority:** Critical · **Sprint:** S1 · **Phase:** 1C · **Stream:** BE

**As** an operator dialog,
**I want** the reason vocabularies read from the database rather than compiled in,
**So that** three dialogs and every historical event render the same 156 rows.

> ⭐ **The client's reason codes arrived 1 Sep 2026 and closed `A4`, `A5` and `A6` after 41 days** —
> the three actions the 23 Jul call called *"reference data the build cannot proceed without"*.
> Propagation wave **`W3`**, the only wave marked *Blocked on client input*, is unblocked.
>
> ⚠ **`[API]` does not declare these three routes yet.** It has 26 endpoint sections and none of
> them is a reason read. **This story amends the specification as well as building it** — which is
> also why it is Critical: [`FW-071`](../../50-frontend/tasks/FW-071.md), [`FW-067`](../../50-frontend/tasks/FW-067.md),
> [`FW-256`](../../50-frontend/tasks/FW-256.md) and [`FW-257`](FW-257.md) all read it.

**Acceptance Criteria:**
- [ ] `GET /reasons/downtime` — the **72** `DowntimeReason` rows with `Bucket`, `DelayCode`, `Description`, `IsNonprodTime`, `DelayBufferMin` and `SupervisorOverride`; filterable by bucket, because the pause dialog wants three buckets and the downtime dialog wants the fourth
- [ ] `GET /reasons/wiprejection` — the **72** `WipRejectionReason` rows, each with the group it carries. ⛔ **`G79`: all 72 group values are ours**, assigned on 2 Sep 2026 against a client sheet that is a flat list with no grouping at all. The response must not present them as client-supplied
- [ ] `GET /reasons/itinhibit` — the **12** `ItInhibitReason` rows: **8 client-active** and **4 `[PLC §8.2]`-only, inactive** (`G80`). Inactive rows are returned **flagged, not hidden**
- [ ] ⚠ **Withdrawn and inactive codes are returned with their flag** so a historical `RunPauseEvent`, `LineDowntimeEvent` or `WipRejection` can still render its reason. Filtering them at the API blanks old rows — the dialogs filter for *selection*, the API does not filter for *display*
- [ ] The composite key is respected: **`FK_RunPauseEvent_DelayCode` is on `(code, bucket)`**, because *Rewind Bundle* is `Nonprod = Yes` under `Setup` and `No` under `Handling`. A response keyed on code alone is wrong
- [ ] `[API §3.1]`'s controller table gains the owning controller, and `[API §4]` gains the three sections
- [ ] ⚠ **The client has not seen the codes we minted.** All 36 new downtime reasons arrived with **blank** `DelayCode`, `Status` and `Delay Buffer` cells, so `SET29`–`SET41`, `RUN15`–`RUN20`, `HDL18`–`HDL25` and the new `DWN##` values are ours. Surface that on the card, not in the payload
