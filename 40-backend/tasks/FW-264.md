## 1. What to build

**Hours:** 28 h BE · **Priority:** High · **Sprint:** S3 · **Phase:** 1B · **Stream:** BE

> ⭐ **The highest-value card in the set, and the only one with no production-code prerequisite.**
> `FlatWire.Domain` has no infrastructure dependency by construction (`D-29`), so this suite needs
> nothing from any refactor and can start the day `FW-263` lands. It is also what lifts `G21`'s
> standing caveat, which is why it leads rather than follows.
>
> ⚠ **If the set is cut, this is the card to keep.** Highest coverage per hour in the service, zero
> production change, no new package pins.

**Acceptance Criteria:**
- [ ] All **15** `AbstractValidator<>` classes covered — every rule, both branches. The fourteen in `RequestValidators.cs` plus `StageRodCommandValidator`
- [ ] Each validator test asserts **the property name AND the `ValidationMessages` constant**, so a message reworded in `Constants/ValidationMessages.cs` without updating the validator is caught
- [ ] All **20 concrete** rule classes covered. ⚠ **20, not 22** — `FlatWire.Domain/Rules/` declares 22 classes ending in `Rule`, and `ConflictRule` and `UnprocessableRule` are the abstract bases the other 20 derive from. **Do not write a test for the two bases**
- [ ] Each rule asserts **its base class** — `ConflictRule` → **409** vs `UnprocessableRule` → **422** — not merely that it threw. `BayAlreadyOccupiedRule` and `RodAlreadyStagedRule` both *feel* like conflicts and only one is
- [ ] ⭐ **`BayAlreadyOccupiedRule` rejects a second rod on the same station WITH NO DATABASE PRESENT.** This is `G21`'s owed evidence and the assertion that lets `[GAP]` drop *"Do not cite this row as proof of defence-in-depth until the domain rule is exercised"*
- [ ] ⛔ **`FootageWindow` overlap arithmetic** — the highest-value assertion in the card. Touching windows (`[0,100]` and `[100,200]`) must **not** overlap; `[0,100]`/`[99,200]` must. Zero-length and reversed bounds covered
- [ ] All **15** `: ValueObject` types covered — the alphas, the dimensioned quantities, both snapshots. Malformed input **throws**; equality is by value; `RunAlpha` rejects `RUN-10000`, the boundary that makes `BusinessKeyGenerator`'s overflow unrepresentable
- [ ] ⚠ Gauge/Width/RollGap rounding asserted at the **persisted** precision — `DECIMAL(8,4)`; a value object that silently accepts 5 dp truncates in the database
- [ ] ⚠ **`RodAlpha("ROD-00041")` throwing is ALREADY proven** by `FW-141`'s startup assertion — this suite asserts it, it does **not** close `G14`
- [ ] ⚠ **`CheckpointType` is five-valued and `EdgeType` two-valued** — this asserts the **C# side of `TC-020` only**. ⛔ The three-way C# ↔ TypeScript ↔ DB `CHECK` diff **stays manual with a named owner** (`[TS §1.2]`); a green suite here is not that check
- [ ] ⚠ **No coverage percentage is configured or gated on** (`[TS §4.1]`, `[SP §9.2]`)
- [ ] One test file per SUT, mirroring the source tree — ⚠ **not** one file per source file; `RequestValidators.cs` alone holds fourteen validators
