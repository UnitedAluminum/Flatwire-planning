## 1. What to build

**Hours:** 10 h BE · **Priority:** Medium · **Sprint:** S2 · **Phase:** 6 · **Stream:** BE

**As a** roll-shop user maintaining edger tooling,
**I want** the edger register readable and writable through the API,
**So that** the Tooling Inventory tab's *Edgers* option has something behind it.

> **This is ordinary CRUD with one non-trivial invariant: the gauges are a CHILD COLLECTION of the
> aggregate, never an independently addressable resource.** A groove has no meaning apart from the
> set it is cut into — `UQ_TIEG_ToolGauge (EdgerToolId, GaugeIn)` says so — and exposing
> `/gauges/{id}` would let a caller orphan one.

**Acceptance Criteria:**
- [ ] Read and write endpoints for `ToolingInventoryEdger`, following `API/Domain/CoilCheckin` as the
      template — ⚠ **`SlitterInterface` is explicitly not a reference** (`[ARC §2.2]`)
- [ ] **Gauges are managed through the parent aggregate only.** Replace-the-set semantics on update;
      no standalone gauge endpoint. A duplicate gauge on one tool answers **422**, not 500
- [ ] `LifecycleStatus` accepts the four values — ⚠ **now `Active` · `In Service` · `In Grinding` ·
      `Inactive`, the client's own fourth word (`D-63`); it was `Retired` until 10 Sep 2026** — and
      **rejects a derived band** — `Active` here is a
      lifecycle state, not a life band. ⚠ **The word `Active` means two different things** across
      this domain; do not let a band leak into the stored column
- [ ] ⛔ **`EdgeType` IS REQUIRED — THIS CRITERION INVERTED ON 10 Sep 2026 (`Q95` leg 5, `D-62`).**
      The column is **`NOT NULL`** in the database and the service must **reject a missing profile**,
      not accept it. ⚠ **And the vocabulary is THREE values here, not the schedule's four:**
      `Full Round Edge` · `Square Edge` · `Broken Edge`. `Natural Round Edge` means *no edging*, so
      no set is ground for it — **reject it on this endpoint** even though `CK_PSC_EdgeType` accepts
      it on a schedule.
      *(Superseded criterion, retained so the reversal is legible:)* `EdgeType` accepts **null** — the client's grid does not classify a set by profile (`D-53`).
      ⛔ Do not "fix" a null by defaulting it to `Round`
- [ ] `MachineName` rejects anything but `FL2` (and null), matching `CK_TIE_MachineName`. The database CHECK is
      belt and braces, not the only guard
- [ ] ⚠ **Enum mirror holds — AND BOTH SIDES OF IT MOVED ON 10 Sep 2026.** `EdgeType` is now the
      client's four profiles (three on this register) and `LifecycleStatus`'s fourth value is
      **`Inactive`**, not `Retired` (`D-63`). ⛔ **The C# enum widening is gated on `OI-05`** — is
      `Bevel` the same as `Broken Edge`? (`Q110` item 1) — because `FW-147` is `done` and its
      enforcement *is* the enum having two members. ⚠ **The TypeScript leg does not exist yet at
      all**; that is `FW-132`, not a defect. Original criterion:
      Enum mirror holds: C# ↔ TypeScript ↔ DB CHECK for `EdgeType` and `LifecycleStatus` —
      the `TC-020` check. ⚠ **`FK_PSC_Edger` kept its name through the re-point**, so any inventory
      keyed on constraint names needs no change
- [ ] Unit tests per `G101`/`D-50`; 100 % on the four metrics is the target
