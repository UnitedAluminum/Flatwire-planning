## 6. Handoff

### 6.1 ⛔ The `ServiceLocator` rule, and the one uncommitted edit

**Nothing in this assembly may call `ServiceLocator.Initialise`, and nothing does.** The rule is
recorded in a `<remarks>` block on `Fixture/NoProviderContext.cs`, which is criterion 12's second
half. ⛔ **That edit is UNCOMMITTED** — 14 insertions, 0 deletions, in the `ual-api` working tree on
`feature/UADEV-23146`.

`FlatWire.Domain/Services/ServiceLocator.cs:20` is why it matters:

```csharp
public static void Initialise(IServiceProvider serviceProvider) =>
    serviceContainer ??= serviceProvider.GetRequiredService<IServiceContainer>();
```

⛔ **`??=` means the first test to touch it wins for the whole assembly** — and under xUnit's default
parallelism, *which* test that is varies between runs. The failure is a green suite that goes red on
a machine that happened to schedule differently.

⚠ **The rule has more teeth than when the card was written.** `Initialise` has exactly **one** caller
in the whole domain — `FlatWire.API/Program.cs:360`, at start-up — and **`FW-266` added `Api.csproj`
to this project's references**, so that caller is now reachable from the test assembly. ✅ Nothing
reads `ServiceLocator.ServiceContainer` anywhere in FlatWire, so no test has a reason to go near it:
**construct the SUT directly, never boot the host to reach a service.**
