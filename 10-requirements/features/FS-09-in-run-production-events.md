## 1. Overview

**Business purpose.** Everything an operator does to a run that is already moving. An **SPC
checkpoint** measures the material and passes or fails it; a **die change** swaps a drawing die over
a paused run and mandates a checkpoint afterwards; a **roll adjust** overrides FM2's roll gap
mid-run; **pause and resume** stop and restart with a reason; and **line downtime** records time
lost when there is no run at all. Each is a dialog over whatever screen the operator is on, and
each writes an event against the run.

⚠ **These are the module's most numerous activities — eighteen, the most of any category — and they
share one shape**: a dialog, an endpoint, a row in one of the five in-run event tables, and a hub
marker. That shared shape is why they belong together and why the phase model already grouped them.

**Functional scope.** Owned by
[`phase-06-in-run-production-events.md`](../../60-delivery/phases/phase-06-in-run-production-events.md),
cited not restated. The SPC checkpoint, roll adjust, pause/resume and die-change dialogs; their five
endpoints and services; **the five in-run event tables**; run-event markers and the `LineStatus`
transitions; the die lifecycle service with per-tool die life and `DieHistory` writes; the
`LineDowntimeEvent` write path and the Line Downtime dialog; the dancer tension log; and the weld
flag guard.

**SPC checkpoints are defined at four points** — incoming rod, post-die-change, FM1 output and
FM2 S3 output.

⚠ **FM2 has THREE stands** and the four-stand model is retired (`D-26`). Component ids are
**position-only** — `FM2_S1` / `FM2_S2` / `FM2_S3` — and roll diameter is **data**. **The 8″ roller
*is* S1.** Edgers at S2 and S3 only; **S3 is final and non-bypassable**. Anything showing four FM2
stands, a separate `8" Roller`, or a 6″ stand named S1 is stale.

**Out of scope.**

- **Weld capture** — [`FS-07`](FS-07-rod-checkin-plc-config.md), because `[REQ §5.6]` puts it at
  the pre-check-in station. ⚠ This category keeps `POST /weldevent` and the **weld flag guard**,
  which is the seam `G26` records.
- **The screen the dialogs open over** — [`FS-08`](FS-08-active-run-monitoring.md).
- **WIP rejection**, which an out-of-spec checkpoint leads to —
  [`FS-10`](FS-10-exceptions-off-ramps.md).
- **The tooling registers themselves** — [`FS-18`](FS-18-administration-reference-data.md) owns the
  die, roll-set and edger registers; this category owns the *events* recorded against them.
- **Wire break**, which is a decided flow with no persistence target —
  [`FS-20`](FS-20-unscheduled-unhosted.md), `G34`.

## 8. Change-impact profile

**What a change here affects.** Events are read by everything that reports on a run.

| A change to… | Affects |
|---|---|
| **the five event tables** | `FS-16`'s SPC and pass-detail reports, `FS-08`'s trace markers, `FS-12`'s coil traceability. `in-review` now, so a late change is a migration |
| **an SPC verdict rule** (`OI-57`, `G51`) | `FS-10`'s rejection trigger, `FS-16`'s CPK reports, `FS-18`'s `AlloyProperty`. **One tolerance value in four places** |
| **the roll-gap write** (`OI-103`) | `FS-04`'s tag surface and the machine itself. The only in-run event that changes machine state |
| **pause/resume** | `FS-10`'s supervisor approval, which shares the path, and `FS-06`'s `LineStatus` |
| **a reason vocabulary** | `FS-18`'s lookups and `FW-254`'s endpoint — one endpoint, several dialogs |
| **die life** (`OI-12`) | `FS-18`'s Die Management screen, deriving from the same table with different bands |

**Existing implementation to modify.** One activity is `in-review` — `FW-171`'s five event tables —
and three are `blocked`. So **the tables that record every in-run event are being reviewed while
the verdict rule (`OI-57`), the pause vocabulary (`G83`) and the dancer model (`G35`) are all
undecided.** This is the fourth category showing that pattern, and here it has a built defect
already: `G51`.

**Regression areas.**

- **`G51` is a live wrong answer, not a gap.** `SpcMeasurement.InSpec` mis-verdicts asymmetric
  bands today, and everything reading it inherits the error.
- **`OI-103`'s unbounded roll-gap change should be treated as a safety item**, not a UX detail.
- **Sharing pause/resume's approval path with `FS-10`** means making it durable changes two
  categories.
- **The `G63` cycle** blocks independent sequencing of pause/resume and rod checkout.
- **Dialog rules are invisible to lint.** A stacked dialog, a scrolling modal or a sub-14 px control
  passes every automated check and fails on the floor.
