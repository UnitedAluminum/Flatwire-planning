# FW-262 - Machine Setup schema — Setup/Handling Times and Material Loss, five tables

**Hours:** 10 h DB · **Priority:** High · **Sprint:** S2 · **Phase:** 1C · **Stream:** DB

**As** the Machines Application's Setup/Handling Times and Material Loss tabs,
**I want** storage for the client's per-line field sets and the standards entered against them,
**So that** the two tabs `FW-003` configures have somewhere to read and write.

## 3. Decisions made here

| | |
|---|---|
| **Catalogue + value, not one wide table** | Order is a requirement, the client has revised the lists twice, two FL3 rows are disputed, and FL3's set is not derivable from FL1's and FL2's. Membership and order are data |
| **All five in `01_Lookup`** | `[DBD §6.2a]` — *"reusable articles and reference data live in `01_Lookup`"*. `02_Schedule` is the pass-schedule triple MVP-1 *"reads and never authors"*, a different lifecycle |
| **`CrewSize` in the key, `TINYINT NOT NULL`** | Verified against the legacy app, not assumed: `Slitters_Standards` holds one row per `(Machine_Idx, Crew_Size)` and the read proc filters on both. **Material Loss takes none** — no selector, no column |
| **A range CHECK on `CrewSize`, not a value list** | The vocabulary is **data**: `united_db.dbo.lookups` category `4061`, with the integer parsed out of a `varchar` description. A hardcoded list would reject a crew size an administrator adds. `[PROPOSED]`, `Q94` |
| **`DECIMAL`, not the legacy `FLOAT`** | No `FLOAT` or `REAL` column exists anywhere in `FlatWireDB`, and a binary float cannot hold a standard time exactly — which matters when 47 are summed into one FL3 setup total |
| **`MaterialLossStandard` separate despite being 1:1** | So *"the DDL seeds the catalogue and never the values"* is true **structurally**. Share one table and `RunAll` inserts rows later `UPDATE`d with real standards — after which the seed guard stops firing and the teardown/rebuild the deploy gate requires destroys them |
| **Both `Pass Change` wordings kept** | FL1 is rod-fed (*Rod Dia.*), FL2 spool-fed (*Input Ga/Width*). 28 rows, 16 distinct labels — not 15 |
| **`Drawblock`/`Drawingblock` not reconciled** | `Drawer`'s own comment records four spellings across four surfaces and says do not reconcile until the Speed tab lands (`A12`, open) |

## 4. Verification

```powershell
python tools/deliverables/verify_schema_counts.py     # all six checks green
cd 30-database\sql
sqlcmd -S "DEV00164-001" -E -C -i FlatWire_DDL_RunAll.sql    # run twice; idempotent
```

```sql
SELECT MachineName, COUNT(*) FROM dbo.SetupHandlingTimeElement GROUP BY MachineName;  -- 33 / 29 / 47
SELECT MachineName, COUNT(*) FROM dbo.MaterialLossElement      GROUP BY MachineName;  --  7 /  9 / 12

-- the labels that MUST exist twice, in different groups WITHIN ONE LINE.
-- GROUP BY MachineName TOO: without it, 'SPC: FL1-Stand 1' looks double-homed
-- because FL1 holds it in H1B and FL3 in H1AA -- two lines, not two groups.
-- The unique key is (line, group, label), so the per-line figure is the one
-- that matters. Verified on DEV00164-001, 10 Sep 2026.
SELECT MachineName, ElementLabel, COUNT(DISTINCT GroupId) FROM dbo.SetupHandlingTimeElement
GROUP BY MachineName, ElementLabel HAVING COUNT(DISTINCT GroupId) > 1;
-- FL1 | Load Spool: Takeup-1 | 2      and      FL1 | Thread: Takeup-1 | 2

-- FL3's two corrected rows, still asserted POSITIVELY so an empty table cannot pass
SELECT g.GroupCode, COUNT(*) AS Rows_,
       SUM(CASE WHEN e.ElementLabel = 'SPC: Takeup-1'    THEN 1 ELSE 0 END) AS HasStaleTakeup1Spc,
       SUM(CASE WHEN e.ElementLabel = 'SPC: FL1-Stand 1' THEN 1 ELSE 0 END) AS HasFl1StandSpc,
       SUM(CASE WHEN e.ElementLabel = 'SPC: FL2-Stand 3' THEN 1 ELSE 0 END) AS HasFl2Stand3Spc
FROM dbo.SetupHandlingTimeElement e JOIN dbo.SetupHandlingTimeGroup g ON g.Id = e.GroupId
WHERE e.MachineName = 'FL3' AND g.GroupCode IN ('H1AA','H1B') GROUP BY g.GroupCode;
-- expect  H1AA | 15 | 0 | 1 | 0   and   H1B | 5 | 0 | 0 | 1
```

✅ **`Q94` LEGS 2 AND 3 ARE ANSWERED — client, 10 Sep 2026 — AND THIS GUARD WAS RE-POINTED WITH THE
SEED.** It previously asserted the *disputed* state (`H1AA 15 | 1 | 0`, `H1B 5 | 0 | 0`) so that a
well-meant correction would fail rather than pass silently. The send-back it was waiting for has
returned, and the two rows had **one** root cause: FL3's `H1AA` SPC row named FL1's **takeup** where
it should have named FL1's **mill**.

- `SPC: Takeup-1` → **`SPC: FL1-Stand 1`** in FL3's `H1AA` — *"This is my mistake, it should have
  contained SPC FL1.FM1 not Takeup1."*
- The **absence** of `SPC: FL1-Stand 1` from FL3's `H1B` was **correct** — *"not necessary as the
  stop is has been completed and these dimensions would not represent final gauge/width."* Which is
  also why FL1 legitimately keeps it in its own `H1B`: FL1's output **is** final gauge.
- `SPC: Takeup-2` → **`SPC: FL2-Stand 3`** in FL2's and FL3's `H1B` — *"FL2 and FL3 should have SPC
  at FL2.FM2 for H1B."*

⚠ **Two things about that third bullet are ours, not his.** *"FL2.FM2"* names no stand, so
**`FL2-Stand 3`** is our reading (S3 is final and non-bypassable; the canonical checkpoint is
*"FM2 S3 output"*), and we applied **replace** rather than **add** — which is what keeps the counts
at `33 / 29 / 47` and the seed total at 109. Adding instead would make FL2 30 and FL3 48. Both are
in the send-back for confirmation.

✅ **Measured on `DEV00164-001` after a teardown-and-deploy, 10 Sep 2026:** `H1AA 15 | 0 | 1 | 0`,
`H1B 5 | 0 | 0 | 1`, totals `33 / 29 / 47`, grand total `109`, and the per-line double-homed set
down to the two FL1 labels above.

## 5. Handoff

- **`FW-003`** (FE) configures the two tabs against these tables. It must map
  `united_db.dbo.machines.machine_idx` **125 → `FL1`, 126 → `FL2`, 127 → `FL3`** itself —
  **no foreign key to `machines` is possible** because it is in another database, so nothing here
  enforces that mapping and a wrong one writes one line's standards onto another silently.
- **The History tab is not served by these tables.** It reads `united_db.dbo.AuditTrail` filtered
  `ModuleId = eModule.Machine`, discriminated by `EntityName`. Two new `EntityName` values are
  needed and the app must keep writing `AuditTrail`. `G92`.
- **`OI-110` stays open.** The evidence now recorded points at `united_db`; `FlatWireDB` is the
  `D-02`/`D-31` decision. If the client answers `united_db`, these five tables move to a
  `30-database/scripts/` cross-database script and every count site moves back.
