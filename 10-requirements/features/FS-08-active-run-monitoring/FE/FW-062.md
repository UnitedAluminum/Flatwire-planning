blocked step needs a register item answered. Keeping them apart is what stops the board reading as

### 3.2 Rules that apply to every step

⛔ These are not repeated in the steps below. They hold for all seventeen.

- ⛔ **Every state write produces a NEW reference.** The trace panel derives its chart from a
  `computed` over its input, so an in-place write leaves the chart frozen while the numbers move

- ⛔ **No per-line `@if`, ever.** The only admissible per-line input is `LINE_PROFILES[machineName]`

- ⛔ **Nothing the API supplies may enter the profile.** `components[]`, `RouteMode`, `weldEvents[]`,

- ⛔ **Create no new class, style or colour**, and verify every class against
  `UALUADEV/src/styles/*.scss` and Bootstrap 5.3 before using it. ⚠ **A CSS class that does not exist

  deferring.
- ⛔ **No `catchError`, no `async`/`await`, no `any`/`unknown`/`never`.** `shared`'s

### Step-5 — The live feed: five streams, one paint per frame

**Scope.** This component's *consumption* of `FlatWireHubService` — gauge, width, speed, footage,
payoff weight and connection state. ⛔ **Not the ring buffer's chart, the maximise behaviour or the
weld markers**, which are [`FW-081`](FW-081.md)'s.

**Implementation.**
- ⚠ **`auditTime(0, animationFrameScheduler)` is the whole performance design for this screen.** The
  readings arrive already batched by the server, but the arrival *rate* is not the client's to choose,
  so every write is collapsed to at most one per frame. Change detection then runs once a frame
  however fast the line is talking, and ⛔ **none of it needs `NgZone`.**
- Readings carry their **footage as a number** as well as a label: the window evicts by *distance*
  and has to recognise a replayed reading after a reconnect, and neither is possible from a string.
- ⛔ **A `null` reading is kept, as a null, and reaches the chart as a gap.** It is never coerced to
  zero and never to target. ⚠ **The filter that used to drop nulls was correct under assumption `A3`
  and is now wrong**: `A3` is retired and `FR-120` superseded (`G120`) — all three lines measure live,
  FL2 at 4 s, which at line speed is one genuine reading every ~80 ft. Deleting a gap is not tidying;
  it is asserting a measurement (`P-344`).
- ⛔ **No client constant may stand for the arrival rate** (`P-345`).

**Dependencies.** Step-3 — the panels must exist to append to.

**Acceptance criteria.**
- [x] Every stream is coalesced to at most one write per frame
- [x] A replayed reading after a re-join is dropped **by footage**, not by count
- [x] A null reading draws a gap and ⛔ **never a flat line at target**
- [x] A payoff weight from the feed matches the read's payoff by a **normalised** position — the read

### Step-12 — The out-of-spec detector and the auto-prompt

**Scope.** Counting consecutive out-of-spec readings per trace and raising the prompt. ⛔ Not the SPC
checkpoint dialog itself, which is `FW-065`'s (Phase 6).

⚠ **Measured finding.** `response.outOfSpec` is on the contract, is never null, and **has no reader**.
Nothing counts consecutive excursions anywhere in the library.

**Implementation.**
- The counter is a **pure function** in `trace-window.model.ts`'s world or a sibling model — it takes
  the retained window and the thresholds and reports whether the prompt is due. ⛔ No component state
  for it, so it carries its own coverage.
- ⛔ **`consecutiveReadings` and `autoPromptEnabled` come from the response and appear as no literal
  anywhere.** The card's *"configurable, default 5"* is the **server's** default, not the client's —
  this is what closes the card's *configurable out-of-spec N* blocker.
- ⚠ **Decide explicitly what a `null` reading does, and record it.** A null is **not** out of spec, so
  it must not increment. ⛔ **It must not reset either** — at FL2's 4 s cadence the gaps *are* the
  data's shape, and a reset would clear a genuine drift every time the gauge dropped a sample. The
  recommendation is **skip**: a null is neither an excursion nor an exoneration.
- The prompt fires **once per excursion**, not once per reading past the threshold — otherwise a
  sustained drift raises a toast every frame.
- Raise through `shared`'s notification service. The primary action opens the SPC dialog, which does
  not exist, so it is a `TODO` naming `FW-065` — ⛔ **not an enabled button over an empty handler.**
- ⚠ The tolerance comparison already carries a `1e-9` epsilon, because binary floating point makes a
  reading exactly on the bound compare as outside it — ⛔ **reuse it; do not re-derive the comparison**,
  or a reading on the bound will raise a spurious prompt.

**Dependencies.** Step-5.

**Acceptance criteria.**
- [ ] N and the enable flag come from `response.outOfSpec`; ⛔ **no numeric literal for either**
- [ ] `autoPromptEnabled: false` raises nothing, whatever the readings do
- [ ] N-1 consecutive excursions raise nothing; the Nth raises exactly one prompt
- [ ] A sustained excursion raises **one** prompt, not one per reading
- [ ] A null reading neither increments nor resets the count, and a spec says so
- [ ] A reading exactly on the tolerance bound is **in spec**
- [ ] The primary action carries a `TODO` naming `FW-065`, and the entry is disabled until it lands
