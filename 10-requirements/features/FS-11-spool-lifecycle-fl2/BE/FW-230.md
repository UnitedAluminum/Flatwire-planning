## 2. The five details

### 2.1 ⛔ AC 1 is withdrawn — read the strike-through, not the sentence inside it

The card's first bullet is **struck text preserved as history**. The superseded design was an
**ignore list** of every prior segment alpha for the rod, read from `SpoolTraceability`, capped
at `VARCHAR(500)`.

**What change `[N]` (26 Aug 2026) does instead:** the mint passes **`''`**, and
`GenerateCoilAlpha`'s **own sweep** finds prior segments — because
[`FW-231`](../../FS-15-shared-schema-boundary/BE/FW-231.md) puts them in `proddb..coils` where the sweep
can see them.

⚠ **Two constraints stop applying to flat wire as a result** — `F11`'s 500-char cap and `F10`'s
2048 → 500 truncation. ⛔ **A developer implementing the struck bullet would reintroduce both**,
and would also build a list the function no longer needs. The DDL says the same thing at the column
itself (`sql/…_03_Materials.sql:535`): *"THE `@ignoreList` ARGUMENT WENT ON 26 AUG 2026."*

### 2.1a ⚠ Two live `Must` requirements still specify the list this story must not build

⛔ **This is the one thing the card does not tell you, and it is a requirements conflict, not a
detail.** The withdrawal is recorded in the decision register, in `[INT §8.0a]`, in the DDL comment
and on the card. **It was never carried into `[BR]`**, where two `Must` requirements still stand:

| Id | Text | State |
|---|---|---|
| **`FR-564`** | *"Each mint shall exclude **every identity already recorded locally for that rod**, across both the spool-segment and coil-part records, **whether or not it also reached the shared schema**."* | `Must` · `[PROPOSED]` — **live** |
| **`FR-561d`** | *"No identity shall appear in both the spool-segment and coil-part records … it rests on the **shared exclusion list (`FR-564`)** and is asserted by test."* `[ORD021]` | `Must` · `[PROPOSED]` — **live** |

⚠ **`FR-564`'s last clause is the anti-registration clause.** *"Whether or not it also reached the
shared schema"* is precisely the case change `[N]`'s mechanism cannot cover: the sweep is
authoritative for **committed rows in `proddb..coils`** and for nothing else. So the withdrawal does
not merely simplify the mint — **it removes `FR-561d`'s only stated enforcement**, and `[DBD]` and
the DDL both still say so in terms: *"It rests on the shared ignore list and is asserted by
`TC-788`"* (`schema/FlatWireSchema_QualityOutput.md`, `sql/…_07_Indexes.sql:247`).

⛔ **`TC-790` is `P1` and directly contradicts this story's build order** — *"The exclusion list
spans both alpha stores."* It cannot pass against a blank-list mint.

**What holds, and what does not.** Registration *does* close the flat-wire-internal case: segments
reach `proddb..coils` via `FW-231`, coil parts via `50_…CompleteCoilOnSkid`, so the sweep sees both
stores and `ORD021` is enforced **by the sweep** rather than by a list. ⛔ **What it does not close
is `Q59`** — a third-party caller passing its own list — and `FR-564` was written to cover exactly
that. So `Q59`'s *"accepted and monitored"* is the residual **and** the reason `FR-564` cannot simply
be deleted.

⛔ **Do not resolve this inside this story.** Build to change `[N]` (`P-231`) — it is the later
decision and the one the shipped procedure and the card both implement. **Raise `FR-564` and
`FR-561d` for a requirements-side ruling** (`P-348`, `OI` in §7): either they are amended to state
registration-plus-sweep as the mechanism, or a narrowed local exclusion comes back and this story's
hours change. ⚠ **Fourteen hours assumes the first.**

### 2.2 ⛔ Alone, this reissues the same name — and then fails hard on the second spool

`GenerateCoilAlpha`'s sweep reads the **shared** coil master. With no FL1 segment rows there, a
blank-list mint sees **no prior sibling** and returns the **first** letter every time —
`R00001A`, on every spool, for the same rod.

⚠ **What happens next is not what the card implies, and the index it turns on is not the one this
plan used to name.** The guard on **this story's** column is **`UX_SpoolTraceability_ChildAlpha`** —
filtered `UNIQUE` on `SpoolTraceability.ChildAlpha`, table-wide. `Q89`'s
`UX_CoilTraceability_ChildAlpha` sits on a **different table** and guards the **coil part**
([`FW-185`](../../FS-12-output-completion-packing/BE/FW-185.md)), not the segment.

So the second spool of a rod does **not** quietly carry a duplicate to a label. Its own insert
violates `UX_SpoolTraceability_ChildAlpha` **inside the same transaction as its mint**, and — given
step 3's atomicity — the whole spool completion **rolls back**:

| Alone, spool 2 of rod `R00001` | Result |
|---|---|
| Mint | Returns `R00001A` again — the sweep sees no sibling |
| Insert into `SpoolTraceability` | ⛔ **Duplicate key on `UX_SpoolTraceability_ChildAlpha`** |
| Transaction | **Rolls back.** No name leaks, no label prints — **and spool completion is blocked** |

⛔ **That makes the consequence operational, not cosmetic:** FL1 cannot complete a second spool off
one rod at all. It is louder than *"silent duplicate-name generator"* and it is worse to ship,
because it stops the line rather than mislabelling one coil. ⚠ **It is only this loud because the
index exists** — the failure is a duplicate-key error naming an index, not a message naming the
cause, so a developer who hits it without reading this section will look for a concurrency bug.

⛔ **`FW-231` is not a nice-to-have ordering preference.** `P-229` records the same rule from the
gating side.

### 2.3 `ChildAlpha` is opaque, and the temptation is to parse it

*"Never parsed, never rebuilt, and no stored letter index."*

⚠ **Every part of the scheme invites parsing it**: the six-character root is a prefix, the
trailing letter is a sequence, and *"single letter for a segment, double for a coil part"* looks
like a grammar.

⛔ **It is a name, not a structure.** Reasons the rule exists:
- ⛔ **The string genuinely does not decompose** — the DDL states the collision outright
  (`sql/…_03_Materials.sql:565`): **`R00001A` + `'A'` and `R00001` + `AlphaLetter(27)` both render
  `R00001AA`.** A parser cannot tell a segment's coil part from a rod's 27th sibling.
- The **function** owns the format; a parser in `FlatWireDB` is a second implementation that
  drifts when `CommonDB`'s changes.
- **A stored letter index** would be a second source of truth for "which letter is next", and
  the whole 26 Aug change is about having exactly one (the sweep). ⚠ **And it would drift by
  design:** *"the generator may skip a suffix already taken by a coil, so an index would drift from
  the letter it claims to explain."*
- ⚠ **`G14`'s format half is enforced by value objects with validating constructors** — that
  validates **shape**, and is not licence to decompose.

✅ **What to use instead, when you want the ordering the letter appears to encode: `SeqNo`.** It is
`SMALLINT NOT NULL` on `SpoolTraceability` and it is the column that carries "order the material
went on" — the DDL says so in the same comment that forbids the letter index. ⚠ **Do not derive the
lead segment as a constraint** — under last-on-first-off it is `MAX(SeqNo)`, but `Q45` is open, so
**derive it in a query**.

### 2.4 The reference loop is a citation, not a call

*"`PlanningDB.dbo.GetCoilAlpha`'s `CONCAT_WS` accumulation — **cite it, do not call it** (it uses
PlanningDB's divergent copy)."*

⛔ **PlanningDB holds a divergent copy** of the alpha logic. Calling it would mint from a
different implementation than the one `FW-231` registers against — producing names that collide
with nothing today and everything later.

**Read it for the accumulation pattern; call `CommonDB.dbo.GenerateCoilAlpha`.**

⚠ **And know that this instruction has a designed expiry.** **`G65`** carries a
`CommonDB` → `PlanningDB` **generator cutover** as one of eight unbuilt waves of the welded-coil
two-alpha change, and `G65`'s own mitigation names this story: *"Sequence the eight waves against
the affected tasks (`FW-186`, **`FW-230`**, `FW-231`)."* ⛔ **Nothing changes today** — the cutover
is designed, not built, and its wave `S1a` is blocked — but if it lands, §2.4 **inverts**, and so
does `FW-231`'s registration target. **Check `G65` before building; do not pre-empt it.**
⚠ **`G65` also carries the `CoilTraceability` → `FlatWire_CoilTraceability` rename**, which would
rename the coil-part index this plan is careful to distinguish in §2.2.

### 2.5 Three guards, not two — and never re-mint

The card says *"replicate the caller's guards: the `' '` blank return and the `UPDLOCK, HOLDLOCK`
re-check."* ⚠ **The caller has three, and the third is the one a segment writer actually needs.**
The reference is `50_…CompleteCoilOnSkid.sql:663`–`:687`:

| Guard | The reference | Why it applies to a segment |
|---|---|---|
| **Blank return** | `THROW 51010` after `LTRIM(RTRIM(ISNULL(…, '')))` | ⚠ **The card's `' '` is imprecise** — the function can return `NULL` **or** whitespace, so normalise **then** test `= ''`. A single-space comparison misses `NULL` |
| **Uniqueness re-check** | `THROW 51011` on `EXISTS (… coils WITH (UPDLOCK, HOLDLOCK) …)` | The function *"sweeps 14 selects over 12 objects but takes no locks"* — so this held key lock is the **authoritative** gate, not the sweep |
| ⛔ **In-transaction sibling** | `THROW 51021` on `EXISTS (… WHERE ChildAlpha = @partAlpha)` over the batch | ⛔ **The segment analogue of `OI-137` / `ORD025` is live** — see below |

⛔ **Why the third guard is not optional here.** `SpoolTraceability` is grained
**`(SpoolAlpha, RodAlpha, SeqNo)`**, so **two segments of one spool off one rod are permitted** —
the DDL concedes the precondition in terms: *"nothing yet forbids one rod contributing two segments
to one spool."* Both would mint blank in **one** transaction off the **same** rod root, and the
sweep sees **committed rows only**, so both get the same answer. That is exactly `OI-137`, one hop
up from the coil parts it was raised for. ⚠ **Without the guard it is still caught** — by
`UX_SpoolTraceability_ChildAlpha` — **but as an opaque duplicate-key error instead of a named
throw**, which is the difference between a five-minute diagnosis and an afternoon.

⛔ **Never re-mint a segment that already has a `ChildAlpha`.** The reference states why, and under
a blank list it is a **correctness** rule rather than an optimisation: *"if an earlier part committed
between attempts the sweep now sees it, so re-minting returns a DIFFERENT letter and orphans the
stored one — and no guard detects that."* Mint only where `ChildAlpha IS NULL`.

⚠ **`ChildAlpha IS NULL` is the whole idempotency key for a segment.** `CoilTraceability` got a
second column for this under `Q89` — `SharedWrittenAt`, *"the retry contract"* — and
`SpoolTraceability` has **no equivalent**. That is consistent **only while mint and insert stay in
one transaction** (step 3). ⛔ **Split them and there is no column that records which side
committed.**

✅ **The root, and where the letter width actually comes from.** A segment mints off the **rod**; a
coil part mints off the **segment** — `GenerateCoilAlpha('R00001A','') → R00001AA`. The reference
writes it as `ISNULL(@partSegment, @partRod)`, and *"rod-fed coils (no segment) fall back to the
rod"* — FL1-standalone and FL3-from-rod. ⚠ **`OI-139` is whether an FL2-standalone spool can arrive
with neither**; the reference's own comment concedes *"if it can, this fallback is not enough."*

## 3. Build order

1. ⛔ **[`FW-231`](../../FS-15-shared-schema-boundary/BE/FW-231.md) ships with this or before it** (§2.2).
2. **Raise `FR-564` / `FR-561d`** before writing code — a one-line question, not a work item
   (§2.1a). ⛔ **Do not build the list, and do not silently drop the requirement either.**
3. Mint only where **`ChildAlpha IS NULL`** (§2.5) — under a blank list, re-minting orphans the
   stored alpha and **no guard detects it**.
4. Call **`CommonDB.dbo.GenerateCoilAlpha(rodAlpha, '')`** — the root is the **rod** for a segment
   (§2.5). ⛔ **Do not build the withdrawn list** (§2.1).
5. **Replicate all three of the caller's guards** (§2.5): `THROW 51010` blank-or-`NULL` after
   trimming, `THROW 51011` on the `UPDLOCK, HOLDLOCK` re-check, and the **in-batch sibling** check
   for two segments of one spool off one rod. ⚠ **One transaction across mint and insert** — there
   is no `SharedWrittenAt` on `SpoolTraceability` to record a split.
6. Store the result in `SpoolTraceability.ChildAlpha` — ⛔ **opaque** (§2.3); ordering is `SeqNo`.
7. ⛔ **Single letter for a segment**; the double belongs to the coil part, off the segment.
8. ⚠ **Test on a shared instance** — LocalDB has no `CommonDB` (§1.2, and `FW-231` §2.5). The
   instance is **`DEV00164-001`**.
9. Record `Q59`'s residual as **accepted and monitored** — `UX_SpoolTraceability_ChildAlpha` is the
   alarm (§2.2), and `Q59` is also why `FR-564` cannot simply be deleted (§2.1a).

## 4. Decisions this plan makes

> `P-##` is continuous across the repository; `P-01`–`P-230` precede this story. ⚠ **`P-348` and
> `P-349` were minted in the 10 Sep 2026 review; mint pointer `P-350`+.**
>
> ⚠ **Written as `P-347`/`P-348` and shifted up one before publication** —
> [`FW-172`](../../FS-09-in-run-production-events/RT/FW-172.md) took `P-347` concurrently the same
> day. ⛔ **Do not "restore" the lower numbers**; `P-347` is spoken for.

### `P-231` — the withdrawn ignore list is not built, and the strike-through is load-bearing

§2.1. The card preserves the superseded design **inside** its first bullet, so a developer
skimming acceptance criteria reads a specification for a thing that must not exist — **and
building it reintroduces `F10`/`F11`'s caps** that change `[N]` retired for flat wire.

⚠ **This is the clearest case in the whole pass of a card whose text says the opposite of its
intent**, and it is why §1 quotes the strike-through rather than paraphrasing.

### `P-232` — `ChildAlpha` is written and compared, never decomposed

§2.3. Extends `D-29`'s value-object stance: the constructor validates **shape**, and nothing
reads meaning out of the string. **No letter index is stored**, because the sweep is the single
source of "what comes next".

**Fallback:** none. A second source of sequence is exactly the defect `G54` describes.
✅ **`SeqNo` is the sanctioned substitute** for the ordering the letter appears to encode (§2.3).

### `P-348` — build to change `[N]`, and raise `FR-564` rather than absorb it

§2.1a. Two `Must` requirements and a `P1` test still specify the exclusion list this story must not
build, and `FR-561d` has **no other stated enforcement**. ⛔ **A plan is derived and loses to a
specification**, so this one cannot retire `FR-564` — but it also cannot implement it without
contradicting the card, `[INT §8.0a]`, the DDL and the shipped procedure.

**The resolution is to make the conflict visible and cheap:** build change `[N]`, and raise
`FR-564`/`FR-561d`/`TC-790` for a requirements ruling in the same pass. ⚠ **The reason this is not
just bookkeeping:** if the ruling reinstates a narrowed local exclusion, the 10 BE hours are wrong,
because they were priced for a mechanism that no longer exists — see §7.

**Fallback:** if the ruling is not available when the work starts, build change `[N]` anyway and
record the gap on `TC-790`. ⛔ **Never the reverse** — a list built "just in case" reintroduces
`F10`/`F11`'s caps and a second source of sequence.

### `P-349` — replicate three guards, and treat `ChildAlpha IS NULL` as the retry contract

§2.5. The card names two guards; the reference has three, and the third covers a shape
`SpoolTraceability`'s own grain permits. ⚠ **The in-batch guard converts an opaque duplicate-key
error into a named throw** — it does not change what is caught, only how long it takes to diagnose,
which is why it is worth the five lines.

**And the never-re-mint rule is load-bearing under a blank list**, not an optimisation: the orphaned
alpha it prevents is the one failure mode in this story that **no index and no test detects**.

**Fallback:** none for never-re-mint. The in-batch guard may be dropped **only** if a constraint
forbids two segments of one spool off one rod — which is `OI-137`'s recommended fix and does not
exist today.
