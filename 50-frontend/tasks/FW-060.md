# FW-060 - Dashboard 1 — Line Status Overview

> ### 🟡 The screen is already built — read this before starting
>
> **DB1 exists** as `supervisor-dashboard.component` in `projects/flat-wire/`, routed at
> `#/flat-wire/supervisor-dashboard`, built ahead of this story alongside DB3.
>
> **Built:** the left nav rail (Shift Summary · WIP Rejections · Pass Schedules · Spool Queue · OEE) ·
> the Flat Wire Mill / Line Status context bar with a shift badge · the shift-statistics strip · three
> `col-4` line cards (FL1 running, FL2 idle, FL3 offline) each with status badge, order / alpha /
> alloy / route, a weight progress bar with ETA, six metric tiles and an SPC footer line · the alerts
> card with a per-alert ACKNOWLEDGE button.
>
> ⚠ **It is a UI skeleton.** Every figure on it is a literal in a private `build*()` method: **no API
> client, no `HttpClient`, no SignalR, no subscription anywhere in the library**, all five rail
> entries `isActive: false` and therefore rendered disabled, and `acknowledgeAlert()` only flips a
> local flag — nothing is persisted. The screen is composition and layout, not behaviour.
>
> ⚠ **The rail is consumed, not written here** — `lib-nav-rail` lives in `projects/shared`
> ([`[UIC §3.22]`](../UIConventions.md)). Do not reimplement it in this library.
>
> ⛔ **Not built, and this story still owes it:** the seven stream subscriptions (`FW-135` /
> `FW-154`) · panel-click routing to DB3 / DB2 / DB5 · the FL2 `null` empty state · the per-payoff
> section and the die-life / SPC section of the line card.
>
> ⚠ **AC 7 is deviated, not merely unmet.** It requires that `payoff-weight-bar` and `alert-banner`
> come from `FW-133` / `FW-134` rather than being reimplemented — and the skeleton builds its weight
> bars and alert rows **inline**, because neither control exists yet. When those controls land, this
> screen's markup must be **replaced by them**, not left as it is.
>
> ⚠ **Two convention deviations are deliberately deferred to this story**, because **DB1 is the last
> screen scheduled** and fixing them earlier would be reworked by the real build:
>
> | Deviation | Convention |
> |---|---|
> | `h-91 overflow-auto` with `align-items-start` and **no height budget**, where DB3 budgets its height and does not scroll | [`[UIC §4.1]`](../UIConventions.md) |
> | The **Live** badge holds still — a plain `fa-circle text-success` with no `live-dot` — where a badge asserting the reading is current must pulse | [`[UIC §3.18]`](../UIConventions.md) |
>
> ⛔ **Neither is a pattern to copy.** Until this story runs, a new screen takes **DB3's** budget and
> DB3's dot rules; both deviations are marked `TODO:` in the component itself.
>
> **No implementation plan has been written for this story yet.** The card below is the contract from
> `[TB]`. Before starting, replace this notice with the sections in the task template: *What to
> build* / *Context you need* / *Build order* / *Decisions made here* / *Verification* / *Handoff*.

## 1. What to build

**Hours:** 44 h FE · **Priority:** High · **Sprint:** S1 · **Phase:** 3 · **Stream:** FE

**As a** supervisor,
**I want** a persistent board showing all three lines live,
**So that** I have floor-wide situational awareness without walking the floor.

**Acceptance Criteria** — 🟡 marks what the skeleton renders; an unticked box is still owed:
- [x] `dashboard-1-line-status` built from `../mockups/dashboard_1_line_status.html` — as `supervisor-dashboard.component`
- [ ] `line-status-panel` per line showing status badge, order/alpha, alloy/route, speed, gauge/width, payoff weight bar + Payoff-2 status, run time — 🟡 **all of it except Payoff-2 status**, which needs the per-payoff section
- [ ] **Gauge/width live on FL1/FL3; blank for FL2 idle** — FL2 standalone broadcasts `null` and the panel must show an explicit empty state, never a flat line at target
- [ ] Subscribes to `lineStatus$ / gaugeReading$ / widthReading$ / speedFpm$ / payoffWeight$ / alertRaised$ / alertCleared$`
- [ ] Clicking a panel routes to that line's Dashboard 3 (running) or Dashboard 2/5 (idle) — ⛔ the cards carry no click handler
- [x] **No header drill-downs to Dashboard 13 / 14** — both descoped 4 Aug 2026, `FR-425` withdrawn
- [ ] Reuses `payoff-weight-bar` and `alert-banner` from FW-133 / FW-134 — not reimplemented — ⚠ **deviated**: both are inline on the skeleton and must be **replaced** by the controls when they land
