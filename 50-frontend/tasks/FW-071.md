## 1. What to build

**Hours:** 24 h FE · **Priority:** Medium · **Sprint:** S2 · **Phase:** 6 · **Stream:** FE

**As an** operator,
**I want** to pause the run against a categorised reason and choose what happens on resume,
**So that** downtime is attributable and every off-ramp is reachable from one place.

> ⛔ **THE VOCABULARY AND THE INTERACTION BOTH CHANGED ON 2 SEPTEMBER 2026 — `D-34`.** The 15
> reasons in five *semantic* categories are **retired**, replaced by the client's **delay-code**
> system: four *time* buckets keyed to the throughput standard-time model. **Literal overlap with
> the 15 is zero.** [`pause_run.js`](../mockups/pause_run.js) has already been reworked to the new
> model and is the baseline; the ACs below were re-pointed at it.
>
> ⚠ **This dialog now carries THREE buckets, not four.** The `Downtime` bucket's 25 `DWN##` codes
> are line-down time and belong to `LineDowntimeEvent`, whose `RunId` is nullable —
> [`FW-256`](FW-256.md) owns that dialog. **`CK_RunPauseEvent_Bucket` rejects a `DWN` code here.**
> ⛔ **Do not add a Downtime tab to this dialog.**
>
> ⛔ **`G83` — four reasons lost their vocabulary and gained no successor**: `OperatorBreak`,
> `ShiftChangeover`, `AwaitingSupervisor`, `SafetyObservation`. They were in the SRS and in this
> card until `D-34`, and the client's 72 codes contain **no equivalent** — `SET11 Prior Shift
> unaccountable` is not shift changeover and `DWN07 Fire Drill` is not a safety observation.

**Acceptance Criteria:**
- [ ] Built from `../mockups/pause_run.js`; expects `pause-btn`, `pause-timer-badge`, `pause-elapsed` and `.line-badge` on the host, and **falls back to the host's own `fwRunCtx()`** so argument-less `onclick="openPauseDialog()"` handlers keep reading live footage
- [ ] **Icon badge + title + purpose line**, a **context chip row** (status · order · alpha · footage · pause start) whose footage and clock **tick live and freeze on confirm**, and a notes row with a 500-char counter
- [ ] ⛔ **The tile grid is gone. 47 codes cannot be tiles at the 14 px shopfloor minimum on an arm's-length panel.** The interaction is `wip_rejection.js`'s, which already solved this: **quick tiles over a `Bucket` select plus a code select carrying the full list** — `Setup` 21 · `RunTime` 12 · `Handling` 14
- [ ] Codes read from **`GET /reasons/downtime` filtered to the three run buckets** ([`FW-254`](../../40-backend/tasks/FW-254.md)) — never compiled in
- [ ] **Payload carries the `(reasonCode, reasonCategory)` PAIR**, not a label. ⚠ **`FK_RunPauseEvent_DelayCode` is composite on (code, bucket)** — *Rewind Bundle* is `Nonprod = Yes` under `Setup` and `No` under `Handling`, so a payload carrying the code alone is wrong
- [ ] ⚠ **`Other` is a code, not a category** — one per bucket (`SET23`, `RUN12`, `HDL15`), each requiring `notes` per `CK_RunPauseEvent_NotesOther`. A caller still sending `reasonCategory: "Other"` is rejected
- [ ] Confirm → timer paused, footage frozen, PLC idle, Dashboard 1 → PAUSED
- [ ] **Four resume outcomes** (`OI-14` closed): `ResumeRun` / `LogWipRejection` / `CheckOutRod` / `ContinuePause`
- [ ] **Rod Checkout is not a pause reason** — it is the fourth resume outcome, superseding `FR-262`
- [ ] Reasons that lead somewhere show a route line before the operator commits — ⚠ **and the route keys on a code now, not a category**: the new `Change Dies` code → opens die change (**suppressed on FL2**), `SET10 QC / Process Monitor Quality` → opens SPC, **roll adjust** carries the frozen footage
- [ ] Each hand-off **closes the pause dialog first, then opens the next** — never both at once
- [ ] Type set at the repo's **14px** floor, not the reference design's 10–13px
- [ ] ⚠ Descriptions render **verbatim** from `DowntimeReason` — *Cannot Find Bundle/Spool*, *Waiting for Spool From Previous Operation*. They are operator labels; *"operators say spool"*, and **`Bundle` means `Rod` and `Spool` means `SpoolProcessing`** here, never the `Q60` `Spool` article

**Rate-card basis:** 2 × modal/dialog @ 12 h = 24 h (§2). ⚠ **Not re-priced for `D-34`** — the interaction is re-aimed at `wip_rejection.js`'s existing pattern rather than a third one being invented, and [`FW-258`](../../60-delivery/tasks/FW-258.md) owns any movement
