## 2. The six primitives

| Control | Detail |
|---|---|
| **`.input` + states** | `.invalid` and `field-error`. ⚠ **The validation *rules* have no home** — `[VAL]`'s new §7.5a records that the client-side validation it claims to own has never been written. Build the **states**; do not invent the rules |
| **Monospace readouts** | gauge / width / footage in `--font-mono` — legibility and column alignment (`[VAL §7.5]`) |
| **`pill-btn` + OK/NG/NA** | pass/fail and the three-state machine-inspection buttons. ⚠ **`G14` is unresolved on whether the inspection is 3- or 4-item** — build the button, let the count be data |
| **`alert-banner`** | raise/clear driven; **auto-dismiss on `AlertCleared`**. Fed by `alertRaised$` / `alertCleared$`, both *immediate, unbatched* (`[SIG §5.2]` rows 8–9). Projects into `FW-130`'s slot |
| **`confirm-bar`** | amber → green gate. The commit control on DB2's wizard and DB5 |
| **`payoff-option`** | selector cards for the payoff bays; consumes `payoffStateChanged$`, whose `state` is `NotStaged \| Staged \| Active \| Blocked` |

⚠ **`Blocked` is a *derived* bay state**, not a fourth `Status` value — `Status='Staged'` plus any
inspection column `='Fail'`. And **`IsWelded` is a flag on a `Staged` row**, not a status, so any
branch on "staged" also matches welded and blocked rods unless it says otherwise. See
`RodPreCheckin.md`.

✅ **A bay's identity is `(Station, PayoffPosition)`, not `(LineId, PayoffPosition)`** — `G21` was
**resolved 15 Aug 2026** as *one physical station*, and this control is where the difference shows.
`RodStaging` gained a persisted `Station` column and `UX_RodStaging_Bay` was re-keyed to
`(Station, PayoffPosition) WHERE Status='Staged'`, **verified on a live deploy**: an FL3 rod staged at
`FL1PO` position 1 is now rejected, where the old line-keyed index admitted it as `(FL3,1)` vs
`(FL1,1)`. ⚠ **So `payoff-option` must not key its cards on the line.** FL1 and FL3 share payoff
hardware, and `Q24`'s off-schedule reversal makes the system switch between those stations by itself —
a card list keyed on `LineId` will show two bays where there is one rod. Related: `FW-209` (4 h,
Phase 4) is the toggle defect on DB2A — it must **reload, not relabel** — and it is the screen-side
consequence of the same decision.

## 3. ✅ Two constraints the repository already satisfies

**Consuming a foundational `shared` component is not a `D-06` violation.** `D-06` forbids copying
*feature-library UI*; `shared`'s primitives are the sanctioned reuse.

| `[VAL §7.5]` constraint | Already present |
|---|---|
| **on-screen virtual keyboard and numeric keypad** | `ngx-touch-keyboard` is a dependency, `NgxTouchKeyboardModule` is imported by `SharedModule`, and `shared` ships a **`KeypadComponent`** |
| **transactional actions must be resolved or explicitly dismissed**, and **supervisor overrides block passive dismissal** | `shared`'s `CommonPopupService` opens **every** modal with `backdrop: 'static'` and `keyboard: false` — both rows are satisfied **by construction** |

⚠ **The failure mode for the second is using `NgbModal` directly**, which carries neither option. Route
dialogs through `CommonPopupService`.

⚠ **One related constraint has no owner**: *no dialog scrolls — an oversized dialog is scaled to fit*
(`--fw-modal-fit` in the mockups' `fw-modal.js`). `NgbModal` covers the dialog runtime but not the
scale-to-fit, and no story owns the Angular half — `[P1A §6.3]`.

## 4. Rules that apply to all six

- **Built fresh from [`../Mockups/`](../Mockups/)**; ⛔ nothing derived from an existing feature library (`D-06`).
- **`--color-*` tokens only** — no `--fw-*` exists (`G18`). The colour semantics are fixed: green = active / in spec · amber = warning / draft-attention · red = fault / out of spec · grey = bypassed or offline · **purple = Draft and the FL3 hybrid route**.
- **14 px floor, set explicitly on `input, select, textarea, button, option`** — they do not inherit the body font and the browser default is 13.333 px. ⚠ The floor rests on `F-14`'s stated dpi assumption; if the panel turns out to be the same size and denser, every size scales ×1.5.
- **Tap targets ≥ 48 px**, and ⛔ **no action may depend on hover** — touch screens have no hover (`[VAL §7.5]`).
- **Button-icon rule, suite-wide:** the **action** button in a dialog footer carries an icon; the **dismiss** button does not. Cancel and Close are plain text.
- **`OnPush`**, and component `.scss` under **10 kB** (a production build **error** past it).

## 7. Handoff

Every screen story consumes these. Hand on **three** things:

1. **`alert-banner` is raise/clear driven, not imperative** — a screen does not "show" it; the event stream does.
2. **`payoff-option` treats `Blocked` as derived and `IsWelded` as a flag** — copy that reading, do not re-derive it per screen.
3. **The keypad and modal-dismissal behaviour are `shared`'s** — consume them; do not rebuild them per screen.
