## 3. The three details

### 2.1 ⛔ `G34` — a decided flow with nowhere to land

`FR-280`–`FR-282` specify the wire-break flow, and **it survived review**. There is **no
persistence target**.

⚠ **Three compounding facts:**
- Its owner **`FW-N08` is uncosted** (`[TB §7]` B.4) and **blocked** — an id exists, hours do not.
- It **shares `FW-202`'s stop path**, so the FL1 spool-completion prompt ladder and the wire-break
  flow observe the **same `RUNNING → STOPPED` edge** — and only one of them can record what
  happened.
- ⛔ **`FW-202`'s prompt is suppressed when an open `RunPauseEvent` already captured a
  non-spool-removal reason** (`TC-174`). **A wire break is exactly such a reason** — so the
  suppression works only if the break was recorded, which it cannot be.

**So the gap is not cosmetic**: it makes a specified suppression rule unreachable.

### 2.2 ⛔ `G35` — blocked on `Q32`, and deliberately without a story

FM2's two dancers are unmodelled **everywhere**. `Q32` decides the shape, and the two answers
produce **different deliverables**:

| `Q32` answer | Deliverable |
|---|---|
| **Scheduled** | A `PassScheduleComponent` row, a DDL column, and a slot in the acknowledgement push — **one table added to the baseline** |
| **Machine-side** | A read subscription; **nothing in the schema moves** |

⚠ **No hours are derivable until it is answered**, which is why the DB index records that a card
would invent a figure. ⛔ **`P-122` already excludes the ten dancer elements from `FW-N05`'s read
list for the same reason** — so the gap is consistently handled, not merely deferred.

### 2.3 AC 4's cross-boundary read is the only relationship MVP-1 has with a schedule

*"Reads wired for … the pass-schedule components **across the external boundary** for scheduled
gaps."*

⚠ **"External boundary" is now a subtlety.** `D-31` (15 Aug 2026) moved the three
`PassSchedule*` tables **into MVP-1**, so they are local tables with **enforced FKs** — not an
external database. What remains external is the **ownership of the data**: MVP-1 **reads**
schedules and **never authors them** (`OI-110`), and `P-13` maps them **read-only with no write
path**.

⛔ **So a "scheduled gap" is read from a local table nothing in MVP-1 populates in production.**
That is correct and is the single most confusing fact in this area.

   still missing**, which is a different link in the same area.

## 4. Decisions this plan makes

> The `P-##` series belongs to [`Backend/tasks/`](../../Backend/tasks/)
> and is continuous across the repository; `P-01`–`P-225` precede this story.

### `P-226` — `G34` is escalated as a correctness gap, not a missing feature

§2.1. It is normally read as *"wire break is not implemented yet"*. It is worse than that: the
flow is **decided**, and its absence makes `FW-202`'s **specified** `TC-174` suppression
unreachable, because the suppression keys on a `RunPauseEvent` reason that cannot be written.

⚠ **So `G34` blocks a rule in a different story**, which is not visible from either card alone.

§3 step 2, and it is `P-195` again. **"Write paths live" is not DB work** — the tables are built
and the writers are `FW-166`–`FW-170`. A DB developer assigned 20 h here has nothing to do.

⚠ **No hours are re-derived** — `[CE]`/`FW-249` own that. This records where the work sits.
