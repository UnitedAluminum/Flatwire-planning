## 2. The three details

### 2.1 ⛔ AC 4's figures are stale, and the card is not the place to fix them

AC 4 says the baseline moves **49 → 50 index statements** and *"the table count stays **28**"*.
Neither is current — the schema has moved repeatedly since (`D-31`, the 20 Aug spool work, the
22 Aug rod↔order work, `Q60`'s merge, `Q89`'s index).

⚠ **`[DBD §6.2]` is the only site that defines the counted baseline**, and this record
deliberately states no figure. **The card's numbers are audit trail** — they were true when
written, on the basis then current.

⛔ **Do not "correct" AC 4 to today's numbers.** That would put a live count in `[TB §7]`, which
is not a permitted site, and it would go stale again at the next `Q##` — the exact defect
[`FW-248`](FW-248.md) exists to catch.

### 2.2 AC 2 is the acceptance, and it has never been run

*"Two concurrent check-ins on one line: one succeeds, the other fails on the index and surfaces
`409 RUN_ALREADY_ACTIVE`"* is the criterion that matters. The index existing proves the DDL ran;
it does not prove the `409` reaches the client.

Three things have to line up, and only the first is done:

1. ✅ The filtered unique index rejects the second insert.
2. ⛔ `FW-146`'s `409` arm translates `DbUpdateException` — **built, but never exercised on this
   index.**
3. ⛔ `FW-157` surfaces it as **`RUN_ALREADY_ACTIVE`**, not a bare `409` — **unbuilt.**

⚠ **The aggregate also enforces the rule in code**, which is why the card calls the index
*"belt-and-braces"*. **That is a hazard for the test**: if the aggregate's check wins first, the
demonstration proves the code path and not the index. **Force the race**, or temporarily bypass
the aggregate check, or the test passes without testing anything.

### 2.3 The `IN` filter must not become `OR`

`07_Indexes.sql:53` warns explicitly. A filtered-index predicate supports `IN (…)` as a single
disjunct and **rejects `OR`**. A well-meaning reformat breaks the deployment — and it breaks it
at `CREATE`, so it fails loudly rather than silently, which is the one mercy here.

⚠ Recorded because the guard is a comment, and comments are what get lost in a reformat.

## 4. Decisions this plan makes

> The `P-##` series belongs to [`Backend/tasks/`](../../Backend/tasks/)
> and is continuous across the repository; `P-01`–`P-191` precede this story.

### `P-192` — the concurrency test must defeat the aggregate check, or it proves nothing

§2.2. The aggregate enforces single-active-run in code and will usually win, so a naive
"two check-ins" test passes via the application path and never touches the index. **The index is
the thing under test**, and it is the only defence under a genuine race.

**Fallback:** if the race cannot be forced reliably, insert directly against the table in two
sessions and assert the second fails on `UX_FlatWireRun_ActiveLine` — weaker on the `409`
translation, but it does test the index.

### `P-193` — the card's stale counts stay stale

§2.1. `[TB §7]` is not a permitted site for the counted baseline, and correcting AC 4 would
create one. **`[DBD §6.2]` states counts; a story card records what was true when it was
written.**
