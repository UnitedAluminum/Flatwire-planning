## 2. Not trimmable, but divisible — and those are different claims

`[TRP §1.4]` says *"It is not trimmable"*, meaning **no control can be cut**. It does **not** say one
developer must build all six. The six are **independent of one another** and share only `FW-130`'s
tokens, so this is where a second and third developer go.

⚠ **Start with `gauge-trace-chart`.** It is the only member with a live-streaming contract behind it
(`FW-081`, `[SIG §5.6]`) and the only one whose **`isLive` input must be runtime-switchable, not
mount-time** — Phase 8's FL2 Live/Profile control and a hybrid FL3 run both require flipping it on a
mounted component.

**FE compresses better than any other stream, and that cuts both ways.** `[TRP §1.4]` prices FE
retention at **0.62** against RT's 0.75–0.90, so the most AI-assisted leverage in the programme sits on
this path. It is also the stream `[DE §4.3]` warns *"is not the constraint"* — compressing this story
does not shorten the programme; it stops this story from holding up eleven phases of screens.

## 3. The six controls

### 3.1 `gauge-trace-chart` — build this first

| | |
|---|---|
| **Mockups** | `dashboard_3_active_run.html` (live) · `_fl2.html` (profile) · `_fl3.html` (hybrid) |
| **Consumers** | DB1 live gauge · DB3 all three variants · `FW-081` live wiring · Phase 8's FL2 variant |
| **Technology** | **Chart.js**, updated in place with `update('none')` — bounded redraw under the ~10 Hz feed (`[CMP §5.5]`) |

**One component with an `isLive` flag, not two components** (`[CMP §5.5]`).

- ⚠ **`isLive` is runtime-switchable.** Not a constructor input, not mount-time.
- **Live mode:** target line, tolerance band, green/red points, weld markers, a fixed window of ~500 points.
- **Profile mode:** the FL2 historical trace is a **REST query** (`GET /run/{runId}/gaugetrace`), and the mockup's profile is **hand-crafted inline SVG, not Chart.js** — so profile mode renders SVG, not a Chart.js dataset.
- ⚠ **FL2 sends `null` live gauge and width, forever, by design** (`FR-120`, `[SIG §5.3]`). A component that waits for `GaugeReading` on `FL2Data` is a defect, not a slow loader.
- **The ~500-point window is now a choice.** At 1920 the same window renders at ~1.5× horizontal pixels per point, or the same density across ~750 points. `[SIG §4]` fixes it at ~500 and `G9` gives no cadence target to derive better from — **pick one deliberately and write it down** (`F-14` rule 3).
- Available already: `chart.js` 4.5.1 with the **annotation**, **zoom** and **datalabels** plugins — the target line and tolerance band are annotation-plugin work, not hand-drawn.
- ⚠ **Live wiring, maximize and the runtime source toggle are `FW-081`, not this story.** Build the shell and its inputs.

### 3.2 `pass-schedule-table`

Read-only component/state table. **Honours `State ∈ {Active, Bypass, Skip}`** — never a boolean
(`FW-132`'s enum, `[API §2]`). Grey = bypassed or offline, per the token semantics. Consumers: DB2's
wizard, DB5, and the acknowledgement step at check-in.

### 3.3 `payoff-weight-bar`

Consumption bar with colour thresholds. **Used directly by Dashboard 1 and as the Payoffs card's
content on Dashboard 3** — `[TB §7]` is explicit that it *"survives as the Payoffs card's content, not
as a sibling of the status panel"*, which is a change to DB3's composition and **not** a deletion.
Feeds off `payoffWeight$`.

### 3.4 `tolerance-viz`

Track + marker + min/center/max labels. **Replaces the retired inline-SVG progress ring** — the
`- Old.html` Dashboard 2 variant is retired and deleted; do not resurrect it. Consumers: DB2 step 4,
DB6's SPC dialog.

### 3.5 `tab-wizard`

Progressive-unlock step strip backing **Dashboard 2's six steps**. The approved DB2 is
**`dashboard_2_rod_checkin.html`**, the guided six-step wizard (`D-08`). ⚠ **That file inlines its own
app bar and omits `flat-wire-topbar.js`** — so when you need a page skeleton, **clone Dashboard 12's,
not Dashboard 2's** (`[SCR §5.6]`).

### 3.6 `action-bar`

Line-mode configurable and **intent-grouped**: Run events · Go to · Run control. The per-line button
sets are fixed requirements, and **FL1 differs from the other two**:

| Line | Buttons | Source |
|---|---|---|
| **FL1** | six — Log Weld Event, Die Change, SPC Checkpoint, Pause Run, WIP Reject, Complete Run. ⛔ **no Roll Adjust, no edger controls** | `FR-107` |
| **FL3** | the six above **plus Roll Adjust** | `FR-108` |
| **FL2** | omits Weld and Die Change (no drawing dies); includes **Roll Adjust** and **Complete Coil** | `FR-109` |

⚠ **Roll Adjust is FL2 and FL3 only.** `[SCR]` Appendix B said FL1 until 27 Aug 2026, and `OI-11` is
still carried as open in the register although `FR-107`–`FR-109` answer it.

## 4. Rules that apply to all six

- **Built fresh from [`../Mockups/`](../Mockups/).** ⛔ **None derived from `shop-floor-common`, `checkin-precheckin`, `common-grid`, `wip-rejection` or `slitter-*`** — `D-06`, and `[ARC §2.2]` calls these *"the rules most likely to be broken by a developer working from habit."*
- **`--color-*` tokens only.** No `--fw-*` exists (`G18`).
- **`OnPush` everywhere**, and the trace component must not re-enter the Angular zone per reading.
- ⚠ **Component `.scss` stays under 10 kB** — `anyComponentStyle` is a build **error**. Shared bulk lives in `FW-130`'s library stylesheet.
- **14 px floor**, including any form control a control hosts. The documented exception is axis labels inside the three compressed DB3 charts — and ⚠ **1080 does not relieve it** (`F-14` rule 1).
- ⚠ **Composition at 1920 × 1080 is new design work with no mockup behind it** (`F-15`). These controls are content-authoritative from the mockups; how they sit on a 16:9 panel is not.
