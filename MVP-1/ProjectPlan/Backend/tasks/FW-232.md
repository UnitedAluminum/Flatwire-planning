## 2. The three details

### 2.1 The shell is priced; the body is not

`FW-227` (26 h, BE 16 · FE 10) owns *the order-boundary handoff and its notification* — the
state machine, hub events 13 and 14, and the two weight latches. **All of that is behind this
route.**

The 3 h here buys: a controller class, one action, one route, the envelope, and the `[API]`
rows. ⚠ **If you find yourself writing an `if`, you are in `FW-227`'s story.**

### 2.2 The handler does not exist, so what does the action delegate to?

AC 2 says *"delegating to `FW-227`'s handler"*, and `FW-227` is unbuilt. `FW-140`'s `P-64`
settles this: **the real implementations ship as shells throwing `NotImplementedException`
named for their owning story**, so a mis-set flag fails loudly instead of serving fixtures in
production.

**Follow that precedent exactly.** The action sends a MediatR command whose handler is
`FW-227`'s shell, or — if no `IOrderService` exists yet — the controller injects the interface
directly per `P-65`, and the dependency moves to the handler later without the interface
changing.

⚠ **`P-65` is still `open`** and needs a signature against `[SVC §3.2]`. It does not block this
story; it decides one line in it.

### 2.3 `[API]` owns the mint, and the count

`P-50`'s whole point is that a plan does not invent a controller. `[API §3.1]`'s table has no
`/order/**` owner and `[API §3.2]`'s index has no row; **both are `[API]`'s to add**, and the
endpoint count moves **22 → 23 there**.

⛔ **This plan states no endpoint count**, for the same reason `[DBD §6.2]` owns object counts.

⚠ **The 1A base-URL freeze is the real deadline.** `FW-132` builds a DI-swappable API client
against a fixed base-URL set; a sixteenth arriving later is a frontend change.

## 4. Decisions this plan makes

> `P-##` is continuous across the repository; `P-01`–`P-168` precede this story.

### `P-169` — the action ships throwing, named for `FW-227`

§2.2, applying `P-64`. A shell that returns an empty success is indistinguishable from a
working endpoint and would let 1A build against a lie; one that throws a named exception fails
loudly and names its owner.

**Fallback:** if `[API]` prefers the route absent until `FW-227` lands, this story reduces to
the `[API §3.1]` mint alone and its 3 h is released. ⚠ **That trades a loud failure for a 404
during 1A's integration**, which is the worse of the two.
