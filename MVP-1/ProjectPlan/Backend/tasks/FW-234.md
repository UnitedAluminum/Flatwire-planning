## 2. The four details

### 2.1 The interface is the deliverable's constraint, not its subject

`SerilogAuditLog`'s class comment is a written contract for exactly this story:

> *"When `P-15` is settled — the recommendation is a `PlcTagAudit` table, the 34th, through
> 1C — add a second `IAuditLog` implementation and change the registration. **No call site
> changes.** That is the entire reason the interface exists."*

So the backend half is: **one new class, one registration line.** If a call site needs
editing, something has gone wrong.

⚠ **Keep the Serilog sink.** The card says *"gains a persisting **sibling** (or a second
sink)"*. A compliance trail that exists only in a database loses the operational value of
being greppable in the log alongside the request that produced it. **Write both** — a
composite `IAuditLog` that fans out to Serilog and the table.

### 2.2 The cancellation token is honoured now, and that changes one comment

`SerilogAuditLog.WriteAsync` deliberately ignores its token, and its comment explains why:
*"Serilog's write is synchronous to its sinks' internal queues, so there is nothing to
await… The token stays on the interface so a durable destination (`P-15`) can accept one
without changing a single call site."*

A database write **does** have something to await. The token is now real —
and that makes §2.4's rule load-bearing rather than theoretical.

### 2.3 `AuditEntry` has no correlation id, and AC 1 requires one

AC 1 lists **correlation id** among the columns. `AuditEntry` (`IAuditLog.cs:101`) has
eight fields and **correlation is not one of them** — `FW-143` flows it through Serilog's
`LogContext`, not through this type.

Two ways, and only one keeps `P-15`'s promise:

- ⛔ **Add a field to `AuditEntry`** — that is a signature change reaching all four call
  sites, which is the thing the interface exists to prevent.
- ✅ **Read it in the implementation** from the same ambient context Serilog reads. The
  persisting implementation resolves the correlation id itself; the record type and every
  caller stay untouched.

**Take the second.** `P-144` records it.

⚠ **`P-112`'s smuggled marker.** `FW-151` had to put a confirmation marker inside the
`Value` *string* because the type had nowhere else for it. **This story does not widen
`AuditEntry` to fix that** — it is a separate decision with the same signature cost, and it
is recorded here so the next reader knows the smuggling is known, not accidental.

### 2.4 A failing audit write must not fail the command

`FR-072` puts the `Attempted` record **before** the push, precisely so a failed push still
leaves evidence. If the audit write itself throws and that exception propagates, the story
has made the system **less** reliable than the Serilog version, which could not fail.

This is `P-138`'s rule — the guarded post-commit replay, where the first throwing broadcast
would have turned a committed command into a `500`. **Guard the persisting write the same
way:** catch, log the failure at `Warning` through the surviving Serilog leg, continue.

⚠ **The guard is on the persistence leg only.** A failure to *construct* the entry — a
missing `OperatorId` — keeps `SerilogAuditLog`'s existing behaviour: log loudly, write an
attributed-to-unknown record, never throw.

## 3. Build order

**DB half (4 h)**

1. `PlcTagAudit` in **`FlatWire_DDL_04_Runs.sql`** — it hangs off the run, like the other
   event tables. Columns cover all eight `AuditEntry` fields plus `AuditEvent` (which of
   the four sinks), `CorrelationId`, and a server-side `CreatedAt`.
   ⚠ **`RunAlpha` is nullable** — a schedule override and a watchdog write have no run.
2. **FKs in `06_ForeignKeys.sql`.** ⚠ `RunAlpha` is a *logical* reference: `G17` makes every
   rod/run alpha reference cross-database in places, and an audit row must survive its
   subject. **Do not FK the audit trail to the run** — a trail that cascades away with the
   thing it audits is not a trail.
3. **Indexes in `07_Indexes.sql`** — one on `RunAlpha`, one on `OperatorId`. These are AC 1's
   two documented query keys and the pair `[PLC §11.3]`'s reviewer filters on.
4. Add to `FlatWire_DDL_RunAll.sql` **in numeric order**; the chain stays contiguous and
   idempotent.
5. ⚠ **Update `[DBD §6.2]`** — the only site that states the counted baseline — and re-run
   `verify_schema_counts.py` to green. **`FW-248` is hardening that guard**; sequence this
   after it if both land in `S1`.

**BE half (8 h)**

6. `PlcTagAuditLog : IAuditLog` in `FlatWire.Infrastructure/Services/`, writing through the
   context's connection. **Follow `FW-150`'s precedent**: `DBQueryHelper` is
   stored-procedure-only, so a plain insert runs Dapper on the context's connection.
7. A composite that fans out to `SerilogAuditLog` and the new one (§2.1), registered as
   `IAuditLog`. **Both legs, and the persistence leg guarded** (§2.4).
8. Correlation id read from ambient context inside the implementation (§2.3) — **not** added
   to `AuditEntry`.
9. Query path through MediatR per `[SVC §3.2]`: `GetAuditTrailQuery` by `RunAlpha` and by
   `OperatorId`. ⚠ **No new controller** — `P-53` withdrew the rod surface and `P-50` stopped
   at fifteen; this is a query handler, and where it surfaces is `[API]`'s call, not a
   plan's.
10. Re-run `FW-143` AC 3 **materially**: write a PLC audit record through the real path, read
    it back by both keys.

## 4. Decisions this plan makes

> `P-##` is continuous across this folder; `P-01`–`P-143` precede this story.

### `P-144` — the correlation id is resolved in the implementation, never added to `AuditEntry`

AC 1 requires the column; adding the field would change the record type and reach all four
call sites (§2.3), breaking the one promise `SerilogAuditLog`'s comment makes about this
story. **The implementation resolves it from the same ambient context Serilog uses.**

**Fallback:** if the ambient context is not reachable from Infrastructure, pass it via a
scoped accessor registered in `FlatWire.API` — still no change to `AuditEntry` and still no
call-site edit.

### `P-145` — both legs, not a swap

The card allows *"a persisting sibling (**or** a second sink)"*. **Build the composite and
keep Serilog.** A trail that leaves the log loses the ability to read an audit record beside
the request that produced it, which is how `FW-151`'s harness found `P-112`. Cost is one
small class.

### `P-146` — the audit table takes no FK to the run

`G17` already makes rod and run alphas logical references in places, and an audit row must
outlive its subject (§3 step 2). **Index `RunAlpha`; do not constrain it.**

⚠ This is a deliberate exception to the schema's enforced-FK stance (`D-04`, `D-31`), and it
is the **only** table where the exception is correct — which is why it is recorded rather
than left to look like an omission.

### `P-147` — the persistence leg is guarded; the audit path never fails a command

`P-138`'s rule, applied (§2.4). A throwing audit write is caught, reported through the
surviving Serilog leg, and swallowed.

reported as accepted, which `G33` says is not proof the line changed. **The trail's honesty
is bounded by `G58`/`G33`, not by this story**, and the `IAuditLog` remarks already say so.
