**I want** the edger register to carry only fields the client actually has,
**So that** the roll shop is not asked for a serial number that does not exist.

> **The table is already built. This story is the reconciliation, not the build.**

> `Edger`. ⭐ **Unlike `FW-259`, the client's grid DID exist and WAS followed** — all fourteen
> columns, in order. This card is the narrower residue: four columns that are **ours** because the
> grid is silent on them (`G104`), and the counted baseline lives only in `[DBD §6.2]`.

**Acceptance Criteria:**
- [ ] **`Q95` q1 applied — `SerialNo`.** If edger sets carry no serial, **drop the column and its
      filtered-unique index** rather than leaving it permanently empty. ⚠ Dropping it moves the
      index count — pair with a recount
- [ ] **q2 applied — `SetNumber` scope, and THE NATURAL KEY ADDED WITH IT.** ⚠ **This is the most
      important leg of the card.** `ToolingInventoryEdger` has **no unique constraint at all** today
      — `Name` (6 Sep) and `EdgerToolAlpha` (7 Sep) were both removed because nothing read them
      (`G104`) — so **two identical rows are possible**. Add `(LineId, SetNumber)` as `UNIQUE` if the
      set letter is unique per line, or `(SetNumber)` if per shop. ⚠ **Filtered**, since `SetNumber`
      is nullable, which makes it an index statement and **moves the count** — pair with a recount.
      ⛔ **Do not answer it by reinstating `Name` or an alpha**
- [ ] **q3 applied — `GrooveNo`.** Real ordering, or drop it. It is `[PROPOSED]` and nullable today
- [ ] **q4 applied — `.100 STD Removal From OD`.** ⚠ **This one is silent if wrong**: the remaining-life
      arithmetic on the tab reads it as *per grind* (`6.00` → `4.75` ≈ twelve). Confirm before any
      screen displays a remaining-grinds figure
- [ ] **q5 applied — `EdgeType` and `EdgerType`.** If the grid's `Type` cell **is** the edge profile,
      **fold `EdgerType` into `EdgeType`** and drop the spare column. If a set is ground for one profile
