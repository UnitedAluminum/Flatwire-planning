**Acceptance Criteria:**
- [ ] Tables created — the Lookup group is **twelve**: `Stand`, `Drawer`, **`ToolingInventoryDie`**, **`ToolingInventoryRollSet`**, `Edger`, `Dancer`, `Spool`, `AlloyProperty`, `PayoffPosition`, **`DowntimeReason`**, **`WipRejectionReason`**, **`ItInhibitReason`** *(`SpoolConfiguration` merged into `Spool`, 23 Aug 2026 — `Q60`)*. ⚠ **The last three are seeded INLINE by `01_Lookup`, not by the sample-data script** — they are production reference data and a production deploy runs `RunAll` alone
- [ ] `FlatWire_SampleData_Lookup.sql` authored — it was **missing**, and the schedule seed depended on it
- [ ] `Stand` seeded with **four rows carrying `RollDiameterIn`**: FM1 12.000 · **`FM2_S1` 8.000 · `FM2_S2` 6.000 · `FM2_S3` 6.000**. Identifiers are **position-only**; diameter is data
- [ ] ⛔ **`Drawer` is TWO rows — `DB1` and `DB2`, the draw boxes.** ~~*"seeded with the 13 size rows (`DIE-0210`…`DIE-0340`) carrying `LastGrindingFeet` and `TotalFeetAllowed`"*~~ — **struck, and this was the dangerous line on this card**: the die split (`Q91`, 2 Sep 2026) moved the 13 sizes out as **physical dies** into `ToolingInventoryDie` (14 rows, the 14th for `DC-0001`'s worked example) with the two die-life counters, and capped `Drawer` structurally at two via `CK_Drawer_Name` + `UQ_Drawer_Name`. **A developer following the old text would rebuild the table the split took apart.** Die change now validates **per physical tool**, not per size
- [ ] `Edger` seeded `Round` / `Square`; `PayoffPosition` seeded with its **3 pinned rows**
- [ ] **`ToolingInventoryRollSet` seeded with six rows** — one set per fitted position: `FM1` 12.000, `FM2_S1` 8.000, `FM2_S2`/`FM2_S3` 6.000 as `Mill`, and `DB1`/`DB2` as `Capstan` (`D-42`, 3 Sep 2026). ⚠ **One set per position is a FLOOR, not the client's count** — *"2 roll set(s)"* reads both as two rolls per set and two sets per position, so `RollQty = 2` is seeded and the row count is left alone. **Do not multiply these rows** until `Q92` returns (`G87`). The capstan spare is not seeded either: *"will be adding a spare"* is future tense
